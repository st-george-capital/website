# Phase 04.1 Plan 02: Null Imputation Bug Fixes Summary

**Surgical fixes eliminating silent null-to-zero imputation in regime clustering and backtest training, plus SPY benchmark gap detection and regime pre-flight guard**

## Performance

- **Duration:** 8 min

- **Completed:** 2026-04-08T00:08:00Z

## Accomplishments

- `buildDailyFeatureVectors` now excludes dates where >50% of z-score dimensions are null, eliminating silent zero-imputation that fabricated "average signal" from missing data
- Backtest `trainRows` loop now skips rows with >3 null dimensions, with per-window warning logs
- SPY benchmark pre-validation throws before the scoring loop if any test-date prices are missing, preventing silent excess-return inflation
- `classifyRegimes` now throws `Insufficient feature data` if vector count < 100 or average magnitude < 0.01, with actionable error messages

## Files Created/Modified

- `lib/macro-engine/regime/cluster.ts` - Replaced null-to-zero imputation with nullFraction guard; excludedDates counter with warn log
- `lib/macro-engine/regime/index.ts` - Added pre-flight check (vectors.length < 100, avgVectorMagnitude < 0.01) before fitClusters call
- `lib/macro-engine/backtest/index.ts` - Added countNullDimensions helper; null exclusion in trainRows loop; benchmark pre-validation block

## Decisions Made

- Dates with >50% null z-scores dropped from clustering (not imputed) — the 50% threshold means a majority of the feature matrix is unknown; including these dates teaches the model on fabricated data
- Train rows with >3 null dims dropped (not imputed) — >3 of 6 is the majority threshold for the same reason; partially observed rows (1-3 nulls) are still included with 0-imputation for remaining dims
- Benchmark validation placed before the weightSetMap construction so the error fires as early as possible in the test window evaluation

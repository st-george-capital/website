  <name>Task 1: Check TimescaleDB availability (blocker)</name>
  <files>lib/macro-engine/db.ts</files>
  <action>
Create lib/macro-engine/db.ts as a server-only module (no "use client") that exports a single async function `checkTimescaleDb()`. This function must:

1. Run: `SELECT name, installed_version FROM pg_available_extensions WHERE name = 'timescaledb'`
2. If no row returned → throw a descriptive error: "TimescaleDB extension not available on this PostgreSQL host. Install timescaledb or switch to a provider that supports it (e.g. Timescale Cloud, Supabase, Neon with timescaledb enabled). Fallback: use plain PostgreSQL with composite index (ticker, date DESC) — acceptable under 2M rows but loses compression and time_bucket()."
3. If row returned but `installed_version` is null → throw: "TimescaleDB is available but not enabled. Run: CREATE EXTENSION IF NOT EXISTS timescaledb CASCADE;"
4. If installed → log the version and return `{ available: true, version: string }`

This function is called as the first step in the db bootstrap and in the ingest orchestrator before any migration or data write.

After running `npx prisma migrate dev --name macro_engine_schema`, manually append to the generated migration SQL file (before running it in production):

```sql
-- Enable TimescaleDB extension (idempotent)
CREATE EXTENSION IF NOT EXISTS timescaledb CASCADE;

-- OHLCV hypertable: 14-day chunks
SELECT create_hypertable('ohlcv_daily', 'date',
  chunk_time_interval => INTERVAL '14 days',
  if_not_exists => TRUE
);
ALTER TABLE ohlcv_daily SET (
  timescaledb.compress,
  timescaledb.compress_segmentby = 'ticker',
  timescaledb.compress_orderby = 'date DESC'
);
SELECT add_compression_policy('ohlcv_daily', INTERVAL '30 days');

-- Macro series vintage hypertable
SELECT create_hypertable('macro_series_vintage', 'observation_date',
  chunk_time_interval => INTERVAL '1 year',
  if_not_exists => TRUE
);

-- Earnings revisions hypertable
SELECT create_hypertable('earnings_revisions', 'date',
  chunk_time_interval => INTERVAL '1 year',
  if_not_exists => TRUE
);

-- OECD CLI hypertable
SELECT create_hypertable('oecd_leading_indicators', 'period',
  chunk_time_interval => INTERVAL '1 year',
  if_not_exists => TRUE
);
```

IMPORTANT: After initial hypertable setup, use `prisma migrate status` (not `prisma migrate dev`) to check migration state — TimescaleDB catalog tables cause spurious diffs with `migrate dev`.

Create lib/macro-engine/types.ts with the UniverseEntry interface and zod schema:

```typescript
import { z } from 'zod';

export const UniverseEntrySchema = z.object({
  ticker:        z.string().min(1),
  name:          z.string().min(1),
  type:          z.enum(['etf', 'equity']),
  sector:        z.string().nullable(),   // null for country ETFs
  country:       z.string().length(2).nullable(), // ISO2, null for sector ETFs
  inceptionDate: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
  proxySeries:   z.string().nullable(),   // AV ticker or FRED series ID
  currency:      z.string().length(3),    // "USD"
  exchange:      z.string().min(1),       // "NYSE", "NASDAQ"
});

export const UniverseConfigSchema = z.object({
  universe: z.array(UniverseEntrySchema).min(1),
});

export type UniverseEntry = z.infer<typeof UniverseEntrySchema>;
export type UniverseConfig = z.infer<typeof UniverseConfigSchema>;
```

Create lib/macro-engine/universe.ts that:
- Reads config/macro-engine/universe.json at module load time using fs.readFileSync
- Validates with UniverseConfigSchema.parse() — throws at startup if config is invalid
- Exports: getUniverse(): UniverseEntry[], getByType(type): UniverseEntry[], getByCountry(iso2): UniverseEntry[], getCountries(): string[]

SMR grade algorithm (O'Neil SMR proxy — revenue/margin/ROE):
```
Given the last 8 quarters of income statement data:
  revenueGrowth  = slope of quarterly revenue / mean revenue (linear trend, positive = good)
  marginTrend    = slope of (grossProfit / revenue) over 8 quarters
  roeTrend       = slope of returnOnEquity over 8 quarters (if available; skip if not)

Score each dimension 0–2 (0 = declining, 1 = flat, 2 = growing):
  revenueScore  = 2 if revenueGrowth > 0.02, 1 if >= -0.01, 0 otherwise
  marginScore   = 2 if marginTrend > 0.005, 1 if >= -0.005, 0 otherwise
  roeScore      = 2 if roeTrend > 0.01, 1 if >= -0.01, 0 otherwise (or skip if data missing)

Total = sum of available scores, normalized to [0, 6]:
  >= 5 → "A"
  >= 4 → "B"
  >= 3 → "C"
  >= 2 → "D"
  else → "E"

If fewer than 4 quarters of data: return null (insufficient history).
```

**lib/macro-engine/signals/analyst.ts**

Export `AnalystConsensus` interface, `fetchAnalystConsensus()`, and `fetchSmrProxy()`.

---

**fetchAnalystConsensus(tickers: string[]): Promise<Map<string, AnalystConsensus | null>>**

Implementation:
1. Check FMP_API_KEY env var — throw with clear message if missing (same pattern as providers/fmp.ts).
2. For each ticker (sequentially — NOT parallel):
   a. Try `/v4/grades-consensus/{symbol}` first. Parse `{ strongBuy, buy, hold, sell, strongSell }`.
   b. If 403/tier error: log warning, set result to null for this ticker.
   c. If 200 but empty object/null: fall back to `/v3/analyst-stock-recommendations/{symbol}` — take the first/latest row, map `analystRatingsStrongBuy`→`strongBuy`, `analystRatingsBuy`→`buy`, etc.
   d. If both fail: set result to null (do NOT throw — cron must continue).
   e. After each ticker: `await new Promise(r => setTimeout(r, 800))` — rate-limit safety.
3. Return a Map keyed by ticker (value is AnalystConsensus | null).

All fetch errors are caught and logged — never thrown. The overlay is enrichment, not a hard dependency.

---

**fetchSmrProxy(tickers: string[]): Promise<Map<string, string | null>>**

Computes O'Neil SMR grade ("A"–"E") for each ticker using FMP income statement data.

Implementation:
1. Check FMP_API_KEY — log warning and return empty Map (all null) if missing. Do NOT throw.
2. For each ticker (sequentially):
   a. Fetch `/v3/income-statement/{symbol}?limit=12&apikey=KEY`.
   b. If 403/tier error or non-OK response: log warning, set result to null. Continue to next ticker.
   c. Parse the array of quarterly income statement rows, sorted newest-first.
   d. Require at least 4 rows — if fewer, set result to null.
   e. Use the last 8 rows (or all rows if fewer than 8, min 4).
   f. Compute SMR grade using the algorithm from the interfaces block above:
      - revenueGrowth = linear trend slope of revenue / mean(revenue)
      - marginTrend = linear trend slope of (grossProfit / revenue)
      - roeTrend = linear trend slope of returnOnEquity (skip if field absent/null)
      - Score each 0–2, sum, map to "A"–"E"
   g. After each ticker: `await new Promise(r => setTimeout(r, 800))` — rate-limit safety, shared budget with analyst calls.
3. Return a Map<string, string | null> keyed by ticker. null means "insufficient data or tier error".

Helper for linear slope: `slope(values: number[]): number` — use least-squares formula
`(n*Σxy - Σx*Σy) / (n*Σx² - (Σx)²)` where x is the index (0, 1, 2...) and y is the value.

All errors caught and logged — never thrown.

**lib/macro-engine/signals/index.ts — extend runDailySignals():**

After writing StockScreenResult rows (from Plan 03), fetch analyst consensus AND SMR proxy for the screened equities and update both fields:

```typescript
const screenedTickers = screenedEquities.map(e => e.ticker);
if (screenedTickers.length > 0) {
  // Fetch both in sequence (not parallel — share the 800ms rate-limit budget)
  const consensusMap = await fetchAnalystConsensus(screenedTickers);
  const smrMap = await fetchSmrProxy(screenedTickers);

  for (const ticker of screenedTickers) {
    const consensus = consensusMap.get(ticker) ?? null;
    const smr = smrMap.get(ticker) ?? null;
    await prisma.stockScreenResult.update({
      where: { runDate_ticker: { runDate: asOfDate, ticker } },
      data: {
        analystConsensus: consensus,
        smrProxy: smr,
      },
    });
  }
}
```

Note: fetchAnalystConsensus and fetchSmrProxy each add 800ms per ticker. With 30 proxy tickers they add ~24s each = ~48s total per cron run. This is acceptable for a daily background job.
